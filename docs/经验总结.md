# DWG 后台批量翻译经验

## 已验证的工作方法

1. **原件冻结，全部操作副本。** 扫描前建立文件清单和 SHA-256；Core Console 的 `/i` 宿主也必须用临时副本，交付时再次验证原件。
2. **先全批次术语，再做三张预译。** 跨图纸使用同一术语表和缓存；有歧义的词保留原文，并把推测中文、上下文和人工确认状态单独记录，不能把推测提升为事实。
3. **网络与 CAD 分开。** 纯 .NET 进程并行请求 API；AutoCAD 数据库 API 只在 CAD 命令线程调用。并发上限应由账户额度和实测限流决定；多个进程共享额度，不能各自无限增加。
4. **覆盖实际使用的内容。** 从模型空间、布局和已插入块递归确定可达内容；排除未使用块、隐藏属性、脚本和字段。XREF、代理对象和栅格图中文字须单列覆盖缺口。
5. **字体必须保存后检查。** 建立微软雅黑样式，先设字体文件，再最后写 `FontDescriptor`；清除冲突的 MText 内联字体。检查中文字体名称、字符集和对象样式绑定。
6. **锁定图层也翻译。** 在输出数据库内暂时解锁，写入后恢复。捕获锁层异常不能算作成功，必须比较保存后的锁定标志。
7. **OLE 工作簿和显示缓存同时更新。** 编辑显示工作表中的字符串单元格，保留数值、公式、合并和样式，再刷新 OLE presentation cache；只有 XLSX 内容变化并不能保证 DWG 显示中文。
8. **OLE 原生序列化需要独立验证。** 本次测试中 DXF 回导丢失了 OLE 存储，CopyFiler 路径可保留句柄和位置；FileFiler 发生过崩溃。不要把单样本成功当作所有 DWG 兼容性承诺。
9. **校验的是实际公式。** Excel 保存可能将普通公式改存为共享公式；比较前必须展开共享公式，并按容差比较计算值。不能只比较 XML 文本或只检查当前内存中的单元格。
10. **后台运行也需要边界。** 隐藏窗口、重定向日志，记录进程归属和超时。检查译文读回、实体句柄、样式、图层、公式、数值及源文件哈希后，才交付新文件。
11. **“数字＋文字”不等于设备编号。** Unicode `\w` 会包含阿拉伯语等文字，容易误跳过编号房间。编号规则应限定 ASCII，并给 Office、WC 等房间标签留出翻译路径，只保护数字和设备后缀。保存后读回一致也不能证明原文没有漏译，必须另查残留房间名和术语冲突。
12. **OLE 与图纸使用同一套已批准术语。** 模型提示词和对象内缓存不足以强制统一。把拼写变体、房间编号和复合名称映射到审定用语，保留来源、作用范围和不确定性；核对后再更新共享执行缓存，不把旧对象译文自动当成权威词表。

## 公开代码与私人数据

仓库包含基础插件、通用后台扫描/写回组件、多语种翻译进程和实验性 OLE 组件。客户图纸、译文、项目术语、运行证据、密钥和商业软件组件均保存在本地，不随源码发布。

通用化后的组件已在本机编译；完整业务批次的证据来自本地项目配置。公开版本仍需使用者提供自己的配置并对代表性图纸验证，不是已经适配任意图纸的一键发行版。
